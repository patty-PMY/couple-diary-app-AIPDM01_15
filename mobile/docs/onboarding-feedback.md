# 註冊、配對引導與操作回饋

## Task 4.1

註冊分為閱讀與確認、建立帳號、Email 驗證三個階段。說明先呈現帳號用途、伴侶可見資料、儲存區域、保存安排、資料移除方式及可選推播用途；成年與同意核取方塊預設不勾選。兩者皆確認且測試說明設定完整後，才顯示 Email／密碼欄位。

返回說明會清除尚未提交的帳號欄位，撤回同意後不能繼續。註冊成功會依 Auth 回應區分已登入或仍需 Email 驗證；需要驗證時提示檢查信箱及垃圾郵件，完成後可保留 Email 回到登入。登入後依配對進度進入配對頁或共享空間。

配對頁依序區分選擇方式、等待伴侶及配對完成。建立邀請和接受邀請擇一；代碼建立後提供分享、有效期間及一次性使用說明。遺失代碼時提示重新產生將使舊碼失效。等待階段會定期更新，也保留手動重新整理；成功後提供共享空間入口。預覽配對清楚標示不會建立真實關係。

## Task 4.2

| 狀態／操作 | 回饋與後續操作 |
| --- | --- |
| 初次載入或重新整理 | 顯示載入指示與目前動作，重新整理按鈕暫停重複操作 |
| 初次讀取失敗 | 顯示可理解的原因及重試方式，不能當作空清單或已確認未配對 |
| 同帳號重新整理失敗 | 保留已載入內容與配對狀態，明示內容可能不是最新版本，提供重新整理 |
| 確認沒有行程／日期 | 顯示空狀態並提供直接新增入口；載入或錯誤時不宣稱沒有資料 |
| 沒有日記／留言／心情 | 顯示對應提示與撰寫、回應或選貼紙入口 |
| 註冊、登入、邀請、分享、登出 | 顯示正在執行的操作，忙碌時停用重複操作；失敗提供下一步 |
| Email 未驗證、帳密錯誤、頻率限制 | 中文說明原因，分別引導驗證、檢查帳密或稍候重試 |
| 網路或裝置儲存失敗 | 分別提示檢查網路或儲存空間；儲存失敗保留輸入 |
| 內容不存在或可能重複 | 提示先重新整理確認，避免盲目重送 |
| 行程儲存成功 | 使用伺服器回傳資料更新畫面，不另依賴刷新結果判定是否成功 |
| 預覽載入失敗 | 不預先切換成預覽身分，也不導向空的共享畫面；可再次嘗試 |

`retrySession` 可重新讀取登入狀態。共享讀取使用請求版本避免舊回應覆寫新資料，載入指示另行追蹤，避免儲存使舊請求失效後仍永久顯示載入。

## 驗證與範圍

- 11 個 Jest 測試套件、80 項測試通過。
- `Onboarding.test.tsx`：iOS／Android 平台設定下各 8 項註冊及配對引導測試。
- `OperationFeedback.test.tsx`：雙平台載入、失敗、空狀態與直接新增，以及行程／日期失敗保留和重試，共 8 項測試。
- `AppFeedback.test.tsx`：實際 AppProvider 搭配模擬 Supabase，驗證初次失敗、快取保留、登入重試、預覽原子切換、預覽恢復及儲存／重新整理競態，共 7 項測試。
- 錯誤對照測試確認原因及下一步，且不把未知後端錯誤原文直接呈現給使用者。
- 型別檢查與 lint 通過；iOS 與 Android 的 Hermes 程式包皆成功產生。

本次為本機程式、模擬原生模組的介面自動測試及打包驗證，未在託管 Supabase 或真實手機操作。不同螢幕與完整無障礙檢查仍屬 task 4.3；存取政策全面檢查屬 task 4.4；實機與完整驗收仍屬 task 5。
