# 雙人日記、留言與心情

## 功能與操作

- 配對雙方均可發布及管理共享日記、留言和心情。編輯只改內容，保留原作者、發布時間及配對；留言不能改掛到另一篇日記。
- 日記依發布時間由新到舊呈現，留言由舊到新，均顯示作者與時間。心情以獨立紀錄顯示記錄者、時間與貼紙，不必先寫日記。
- 日記上限 500 個 Unicode code point，留言上限 100 個，emoji 不會因 UTF-16 代理對被計為兩字。輸入框顯示使用量與剩餘字數，不截斷超限內容；超限或僅有空白時拒絕送出。
- 儲存成功後才更新清單及清空發布輸入；失敗時保留原輸入，可重試。伺服器成功回應後直接合併回傳資料，避免寫入成功後重新整理失敗而誤報發布失敗。
- 選擇心情後須按「確認記錄心情」才儲存，可以取消選擇。心情紀錄可編輯或刪除。
- 刪除內容須確認，可取消；刪除日記會連帶移除留言。配對以外及未配對帳號不能讀寫共享內容，未配對介面不顯示發布入口。
- 本機預覽使用裝置儲存；正常登入使用 Supabase。可用「重新整理日記」讀取伴侶最新內容，不宣稱即時同步。

## 資料庫遷移

依序套用既有遷移後，套用 `supabase/migrations/20261111050000_journal_management.sql`。本次已在隔離 PostgreSQL 驗證，尚未部署到託管 Supabase。

新 trigger 保護原作者、ID、配對與建立時間，並禁止變更留言所屬日記。後端使用與 ECMAScript `String.trim()` 相同的空白集合及 PostgreSQL `char_length`，驗證 500／100 字限制與非空白規則。配對成員可更新內容，插入時仍要求 `created_by = auth.uid()`，資料隔離由 RLS 執行。

## 自動驗證

- 型別檢查與 lint 通過。
- 完整 Jest 測試：7 個套件、47 項測試通過。
- iOS 與 Android 的 Hermes 程式包皆成功產生；此項屬於打包檢查。
- `DiaryScreen.test.tsx` 使用 React Native Testing Library，分別設定 iOS 與 Android 的平台分支，驗證發布、編輯日記與留言、先選後確認心情、修改心情、取消與確認刪除、日記留言連帶刪除、重新載入、emoji 邊界、Unicode 空白、儲存失敗保留與重試，以及未配對狀態。
- 介面測試使用實際 AppProvider 與預覽資料邏輯，僅模擬裝置儲存、Safe Area 及與日記無關的通知服務；不連線真實 Supabase。
- `supabase/validation/verify.mjs` 共 13 項檢查通過，新增日記 CRUD、500／501 字與 100／101 字 emoji 邊界、Unicode 空白拒絕、原作者保護、留言所屬日記保護、有效心情、留言連帶刪除及跨配對／未配對隔離測試。

## 裝置驗收範圍

平台分支的介面自動測試與程式包產生，不等同於真實 iOS／Android 裝置驗收。本次環境未提供可用的兩平台裝置與託管 Supabase 設定，未驗證系統鍵盤、螢幕閱讀器、實際網路失敗及兩台裝置同步。任務 5.3 仍須進行實機驗收，並記錄結果。

以兩個已配對帳號分別在 iOS 與 Android 驗證：輸入 500 個 emoji 日記、100 個 emoji 留言，確認超限保留、失敗重試、對方重新整理可見、編輯保留原作者、心情確認與管理，以及刪除日記後留言消失；另以其他配對帳號確認不可存取。
