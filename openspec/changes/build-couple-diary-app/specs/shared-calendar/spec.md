# Spec Delta

## Purpose

讓配對情侶能在同一個行事曆新增並查看彼此的每日行程，降低安排見面時間時的資訊落差。

## ADDED Requirements

### Requirement: 新增共享行程
系統 SHALL 允許已配對使用者為所屬配對新增行程，並要求行程標題與日期時間。

#### Scenario: 新增有效行程
- **WHEN** 已配對使用者提交包含標題及有效日期時間的行程
- **THEN** 系統儲存行程並將其加入該配對的共用日曆

#### Scenario: 行程資料不完整
- **WHEN** 使用者提交缺少標題或無效日期時間的行程
- **THEN** 系統拒絕儲存並指出需要修正的欄位

#### Scenario: 尚未配對時新增行程
- **WHEN** 未完成配對的使用者嘗試新增共享行程
- **THEN** 系統引導使用者先完成配對，且不建立共享資料

### Requirement: 管理共享行程
系統 SHALL 允許配對成員編輯及刪除所屬配對的行程。

#### Scenario: 編輯共享行程
- **WHEN** 配對成員提交有效的行程標題或日期時間變更
- **THEN** 系統儲存變更並在共用日曆顯示更新後的行程

#### Scenario: 刪除共享行程
- **WHEN** 配對成員確認刪除所屬配對的行程
- **THEN** 系統刪除該行程且不再顯示於共用日曆

### Requirement: 查看共享行程
系統 SHALL 依日期呈現配對雙方建立的行程，並標示建立者、行程時間及時區。

#### Scenario: 查看指定日期行程
- **WHEN** 配對使用者開啟共用日曆並選擇日期
- **THEN** 系統顯示該日期雙方可存取的行程、建立者、時間及時區

#### Scenario: 尚無行程
- **WHEN** 使用者查看沒有行程的日期
- **THEN** 系統顯示空日期狀態並提供新增行程的入口

### Requirement: 行程資料的配對隔離
系統 SHALL 將每筆行程限定於建立者所屬的配對。

#### Scenario: 其他配對嘗試存取行程
- **WHEN** 非該行程所屬配對的使用者嘗試讀取或修改行程
- **THEN** 系統拒絕請求且不揭露行程內容
